> 💡 **第一性原理提示**：规格驱动开发（SDD）最大的敌人不是初期设计失误，而是代码演进后文档腐烂导致的“文档漂移”。`egm-drift-report` 将设计文档维护为“活体规格（Living Specification）”，强制通过双向比对（文档未落地的声明 vs. 代码中未记载的逻辑）与仅报差异的信噪比过滤，把隐性偏离转化为可分诊的日期化报告。

# 检测设计与代码之间的漂移

在 Codex 或 ChatGPT Work 中运行时，请先阅读 [Codex 集成指南](../../docs/codex.md)。
在 Claude Code 或 Cowork 中运行时，请先阅读 `${CLAUDE_PLUGIN_ROOT}/docs/claude.md`。

当用户要求对所有设计文档或一组 README 执行漂移检测时，目标是找出代码库与文档所述规格发生偏离、或尚未按规格实现的所有位置。

1.  **检查输入**：确认已提供包含设计文档或 README 的目录。若未提供，请询问用户指定目标目录。
2.  **列出文档**：列出设计目录中的所有文件。
3.  **逐一分析**：针对**每一份**设计文档：

    *   **建立上下文**：阅读该设计文档。识别其意图、拟议变更以及提及的具体文件名/符号。
    *   **定位源码**：在源码树中找到对应的源代码文件。如果路径未显式给出，使用代码搜索或 grep 定位文档中提到的相关类、函数或 API 端点。提示用户为文档补全缺失的链接，以降低未来检测的成本。
    *   **核验现状**：读取这些源文件的当前状态。
    *   **检测漂移**：将设计与现实逐项比对。重点排查：
        *   缺失特性（Missing Features）：文档中描述但代码中缺失的逻辑。
        *   不完整模型（Incomplete Models）：Dataclass/类/结构体/Proto 中缺失设计指定的字段。
        *   逻辑捷径（Logic Shortcuts）：原计划采用动态逻辑却使用了硬编码值。
        *   架构偏离（Architectural Divergence）：实际实现采用了与提案不同的模式/库。
    *   **过滤输出**：**只**报告差异。不要描述哪些部分正常工作或完全匹配。如果代码与设计完全一致，仅输出 `"No drift detected."`（未检测到漂移）。

4.  **生成报告**：产出一份汇总所有发现差异的单一报告。

    *   使用文件写入工具将每个文件的分析结果追加到 `{YYYY-MM-DD}_DRIFT_REPORT.md`。
    *   严格格式：

        ```markdown
        ## <DESIGN_DOC_NAME>

        <列出发现的具体偏离项的无序列表>
        <或 "No drift detected">
        ```

5.  **执行指引**

    -   务必严谨。如果设计文档提及了某个具体对象、字段或文件名而代码中不存在，这就是可报告的漂移。同时进行双向覆盖核查：如果代码中存在某部分逻辑但未在设计文档或 README 中被引用，同样属于可报告的漂移。
    -   充分读取文件，确保你核查的是代码的当前真实状态，而不是依赖记忆。
    -   按顺序逐个处理文件，以防止工具输出缓冲区溢出。
