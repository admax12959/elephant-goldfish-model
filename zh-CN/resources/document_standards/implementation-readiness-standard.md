> 💡 **第一性原理提示**：实现就绪标准的核心是「零决策规则（Zero-Decision Rule）」——把所有架构选择、边界条件和文件写权限白名单都在写代码前彻底敲定。它确保进入编码阶段的执行者（无论是人类还是新鲜上下文的 AI）只需忠实执行蓝图，不会在写代码时临时“即兴发挥”或顺手重构无关文件。

# 实现就绪标准

本标准定义了实现计划与任务列表的质量标尺。

## 核心原则

只要一名不熟悉代码库的合格工程师（或新鲜上下文的 AI 会话）能够按该计划执行，并在首次尝试时就产出正确的变更——全程无需猜测、无需追问澄清、也无需自行做设计决策——该计划即为合格。

## 零决策规则

计划必须做到**不把任何设计或架构选择留给实现者**。如果实现者必须自行做出设计选择（包括但不限于选择数据库 Schema、设计 API 路径、挑选依赖库，或决定如何处理新的边缘情况），则该计划**未通过**本标准。所有此类决策必须预先确定并记录在计划中。

## 分阶段与检查点

计划必须将工作划分为逻辑清晰、渐进式的阶段。每个阶段完成后都必须使代码库保持稳定、可构建且可测试的状态。

## 要求（非穷尽示例）

如果适用于拟议变更，计划必须详述以下方面：

*   **目标范围与文件边界（Target Scope & File Boundary）**：明确列出将要创建、修改或删除的精确仓库相对文件路径，足以用于强制执行阶段五写入白名单，防止未经批准的相邻重构或顺手添加依赖。仅对文件名无法预先得知的生成产物使用目录通配符（glob）。
*   **可执行步骤（Actionable Steps）**：针对每个文件的精确逻辑变更、数据转换与 API 更新。
*   **测试计划（Test Plan）**：必须实现的具体测试用例（包括正常路径与边缘情况）。
