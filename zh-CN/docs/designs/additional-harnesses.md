# 扩展编程智能体宿主环境支持

- **作者：** [@n3wth](https://github.com/n3wth)
- **状态：** 提案（Proposal）。维护者范围审批与设计评审待定。
- **日期：** 2026-10-24
- **跟踪 Issue：** [Cursor #145](https://github.com/google/elephant-goldfish-model/issues/145)、[OpenCode #146](https://github.com/google/elephant-goldfish-model/issues/146)、[Copilot CLI #147](https://github.com/google/elephant-goldfish-model/issues/147)

## 问题与目标

大象-金鱼模型 (EGM) 需要的不仅是一个能发现 `SKILL.md` 文件的宿主环境。评审员必须能够读取共享的智能体人格与文档标准、在新鲜上下文中运行，并产出可审计的结果。仅复制技能文件会导致相对资源路径失效。

本提案将共享的 EGM 工作流扩展至 Cursor、OpenCode 与 GitHub Copilot CLI。为每个宿主编写轻薄的适配器并复用现有的工作流测试用例。针对每个宿主独立验证支持情况：允许某个宿主保持实验性状态，同时另一个宿主通过验证。

本提案不改变任何运行时行为，也不构成任何支持声明。它独立于 #135、#136 与 #137 中的打包和发布 PR 栈。实验性实现可在基于本设计叠放（stacked）的草稿 PR 中提前准备，但维护者范围审批与设计批准仍是合并前提。草稿实现不代表宿主支持，也不能替代真实环境验证。

## 范围

目标：

- 将技能、智能体人格、文档标准与必需指南作为完整包一并安装。
- 保留头脑风暴、起草、评审、人类审批门禁与文件产物机制。
- 在需要时启动具备可强制执行只读权限的新鲜上下文评审员。
- 分别记录安装、工作流与隔离性验证结果。
- 复用既有测试场景与集成夹具（fixtures）；跟进 #112 中的共享测试抽取，但无需等待新框架落地。

非目标：

- 构建通用的宿主注册表、传输层、兼容服务或编排框架。
- 为每个宿主分叉（fork）权威技能或智能体人格文本。
- 基于 CLI 或本地 IDE 运行成功，就宣称支持 VS Code 中的 Copilot、Cursor 云端智能体或其他形态。
- 在常规 CI 中运行付费测试、绕过平台策略或推进市场上架。
- 在此实现 Hermes、OpenClaw 或 Delta（相关工作归属 #116 与 #119）。
- 在本次迭代中支持 Factory Droid 或 Pi。

## 现有组件与权责划分

共享行为保留在 `skills/`、`agents/`、`resources/` 与各宿主指南中，参见 [harnesses](../harnesses.md) 与 [testing](../../TESTING.md)。

每位宿主贡献者负责维护适配器、安装指南、离线检查与真实测试记录。维护者审批范围，并决定测试记录是否足以支撑“受支持”声明。人类用户掌握设计决策以及其他必需的工作流步骤审批权。

适配器可以定义宿主如何定位插件及其资源，也可以定义委派指令与工具限制；但必须读取共享的智能体人格文本，绝不能另行维护一份评审规则副本。

## 架构与数据流

1. 宿主在固定版本下将 EGM 候选包安装至其原生包位置。
2. 编排器加载共享技能并从该包内解析资源。
3. 每名评审员在全新对话中启动，其任务包含智能体人格路径、目标产物、所需文档标准及必要源码路径。
4. 评审员读取这些资源并通过宿主的结果返回机制提交发现项。它不接收父会话对话、作者辩解、记忆或无关评审员的发现项。仅当权威阶段显式要求并将其列为输入时，才传递前置报告（例如阶段 8 需要阶段 5 的 `zoom_out_report.md`）。
5. 编排器等待所有预期评审员完成、识别失败项、写入报告，并在既有人类审批门禁处暂停。

当宿主不支持嵌套委派时，采用直接派发（direct dispatch）。缺失的评审员绝不能被表示为评审通过；应报告阶段不完整并询问用户如何继续。在宿主实际需要前，推迟引入选择性重试机制。

评审员具备只读权限；起草与报告撰写角色仅保留产出所需的工作区权限。不得为了迁就安装或委派而全局削弱宿主权限。

仅凭全新对话本身不足以证明评审员隔离。宿主注入的指令、记忆、MCP 访问以及共享工作区文件必须单独评估。上下文隔离不等同于文件系统隔离或进程隔离。需评估评审员是否能通过共享文件系统读取无关报告；仅在提示词中嘱咐“不要读取”不能证明强制隔离。未知的原生隔离状态必须记录为“未验证（unverified）”，绝不可记为通过。

### 人类审批门禁

保留权威技能中定义的全部门禁：

- [Brainstorm](../../skills/egm-brainstorm/SKILL.md)：在派发金鱼评审员前确认就绪，并在交接前批准构想简报。
- [Draft](../../skills/egm-draft/SKILL.md)：确认输入采集并获得起草批准；逐节审批；未指定目标路径时确认写入位置。
- [Review](../../skills/egm-review/SKILL.md)：未指定预设时由用户选择预设；保留必需的阶段检查点与暂停/继续选择。
- [Resolve](../../skills/egm-resolve/SKILL.md)：在应用经用户批准的编辑前，先呈现建议修复与提出异议的发现项。

当宿主没有结构化提问工具时，使用普通聊天交互。在选定工作流需要人类响应的每一处都必须等待。非交互式测试夹具中的预先批准不能替代交互式暂停验证。

## 宿主适配器方案

| 宿主环境 | 拟议机制 | 必需验证证据 |
| --- | --- | --- |
| Cursor 本地 Agent | 原生插件包与使用宿主只读设置的自定义子智能体。通过轻薄适配器提示词复用共享智能体人格文件。 | 验证已安装资源路径、只读权限强制执行、宿主完成记录以及子智能体实际接收的上下文。 |
| OpenCode CLI | OpenCode 1.18.29 V1 配置，含原生命令、技能别名与受限 JSON 智能体定义。在暴露入口技能前先安装完整 EGM 目录树。 | 验证 `task` 派发、`permission` 强制执行、隔离的子会话以及相对包路径的资源读取。 |
| GitHub Copilot CLI | 原生插件安装与带有显式工具白名单的自定义智能体配置文件（profiles）。对评审员禁用仓库指令自动注入。 | 验证已安装包布局、子上下文、共享智能体人格读取、工具拒绝以及可靠的结果回收。 |

针对选定的宿主版本逐一确认原生插件清单与路径，不要假设兼容 Claude 的语法就能保证等价行为。

Cursor 候选方案针对 CLI `2026.10.01-e373342` 进行离线发现。其 `.cursor-plugin/plugin.json` 选择了 `skills/`、`.cursor-plugin/agents/` 与 `.cursor-plugin/rules/`。每名评审员声明 `readonly: true` 与 `permissionMode: readonly`（固定版本 CLI 加载器需要后者才能注册只读权限）。离线发现找到了 7 个技能、7 名评审员与 1 条激活路由规则。原生强制执行仍未验证。

OpenCode 实现针对 1.18.29 版本与 V1 接口，生成独立的 `opencode.json`，包含 `agent`、`command` 与 `skills.paths` 条目。评审员使用 `mode: subagent` 以及允许本地 `read`、`glob`、`grep` 操作的 `permission` 规则。由于 V1 将 MCP 资源读取映射到 `read` 权限，必须显式拒绝 MCP 资源读取。主智能体通过 `task` 搭配已注册的 `subagent_type` 调用，并在新鲜评审时省略 `task_id`。原生 CLI 离线接受了该配置并发现了 7 个已安装技能。运行时强制执行与上下文隔离仍未验证。切勿将该映射与 V2 的 `subagent` 或 `permissions` 接口混用。

Copilot CLI 候选方案针对 1.0.82 版本与根级 Agent Plugins 1.0 `plugin.json`。配置文件位于 `com.github.copilot/agents/*.agent.md`，原生 ID 为入口智能体 `egm:egm` 与评审员 `egm:<persona-name>`，技能保留在 `skills/*/SKILL.md`。原生会话清单在未发起模型请求的情况下发现了全部 8 个配置文件与 7 个启用技能。评审员配置 `tools: [read, search]`、`include-custom-instructions: false` 与 `user-invocable: false`。真实环境下的权限强制执行与隔离性仍未验证。

保留各宿主指南中现有的产物目录契约，报告文件写入位置，此处不引入新的默认输出目录。

## 验证与发布门禁

### Grok Bot 兼容性

在 #145 下单独评估 [Grok Bot](https://cursor.com/docs/grok-bot)。其持久化记忆与共享云端计算环境不同于 Cursor 本地 Agent。[Grok Bot 指南](https://cursor.com/docs/grok-bot/work) 虽描述了技能与机器人交接，但并不证明与 Cursor 适配器兼容。

需逐项检查包导入、必需资源读取、新鲜评审员上下文、只读强制执行、完成记录以及人类审批暂停，并检查评审员记忆与共享文件是否会暴露过往发现项。在这些检查通过前，保持支持状态为未验证。通过 Cursor 本地 Agent 运行不能代表支持 Grok Bot。若需专门实现，应在评估完成后另行提案。

### 共享检查

复用现有技能测试套件中的提示词与断言：[brainstorm 场景](../../skills/egm-brainstorm/test_scenarios.yaml)、[draft 场景](../../skills/egm-draft/test_scenarios.yaml) 与 [review 场景](../../skills/egm-review/test_scenarios.yaml)。将 [`tests/integration/test_codex.py`](../../tests/integration/test_codex.py) 中的标记探针与行数工作流夹具，以及 [`tests/integration/test_claude.py`](../../tests/integration/test_claude.py) 中的项目指令与父标记探针作为行为参考。它们的原生追踪读取器与宿主强绑定，应为每个新宿主适配证据采集逻辑，不要复用不兼容的解析器。公共运行器与结果 Schema 仍在 [#112](https://github.com/google/elephant-goldfish-model/issues/112) 中后续推进。

离线检查必须覆盖：

- 清单解析以及与现有包的身份/版本一致性。
- 已安装布局中所有被引用的智能体人格、文档标准与指南路径。
- 适配器工具限制以及不存在共享行为的拷贝副本。
- 引入原生证据解析器时，需包含缺失启动记录、缺失完成记录、畸形记录与 Unicode 行分隔符的测试夹具；先基于真实宿主记录确定 Schema，再复用适用的解析器与夹具。

真实环境检查仅在用户显式请求时运行。使用干净的宿主配置文件与固定版本的候选包，运行 brainstorm、draft 与 review，并包含真实的人类审批暂停。若原始证据包含账号数据，应私下妥善保存。

每次运行均需记录：候选 SHA、产物校验和或已安装文件身份、宿主版本与运行形态、模型标识及日期。分别记录安装、工作流与隔离性结果，并依据宿主自身记录（而非仅凭父智能体总结）核实评审员启动与完成情况。

隔离性检查必须在父对话中植入仅父会话可见的随机标记，验证子智能体完成必需读取，并在条件允许时检查宿主注入的上下文。仅凭“未复述标记”本身不足以证明隔离。使用一次性测试夹具探测只读强制执行，确认评审员无法修改文件。

若宿主记录不可访问，必须明确保留“未验证”的隔离性结论。通过安装检查绝不能把未知的工作流或隔离性结果升级为通过。所有结论均限定于被测宿主版本、模型与运行形态。

仅在安装、工作流与隔离性三类检查全部通过后，才将该宿主加入支持矩阵。缺乏委派能力时必须以清晰的不支持提示中止评审，严禁在主上下文中内联模拟独立评审员。

## 备选方案考量

| 备选方案 | 决策与理由 |
| --- | --- |
| 通过通用安装器仅安装技能 | 单独使用不充分：EGM 依赖技能目录之外的智能体人格与文档标准。仅在证明完整包可访问时方可使用。 |
| 为每个宿主完整拷贝整个运行时 | 拒绝：重复内容必然漂移。保持源内容共享、适配器轻薄。 |
| 让评审员复用父会话对话 | 拒绝：破坏金鱼零上下文隔离。 |
| 先构建通用适配器框架 | 拒绝：三个具体集成不足以支撑抽象新框架；待出现明显重复后再抽取公共逻辑。 |
| 收录热门仓库列出的每一个宿主 | 拒绝：其他项目的流行度不能证明满足 EGM 的安装与隔离要求。 |
| 仅维护当前已有宿主 | 维护成本最低，但无法满足 #145–#147 代表的社区诉求。在验证人力到位前，维护者可暂取此策略。 |

## 风险与缓解措施

- 宿主 API 漂移：在测试记录中固化精确版本号，并为适配器补充回归检查。
- 模型成本过高：手动运行小型夹具并在可用时记录用量。
- 维护负担膨胀：保持各适配器彼此独立，避免引入未使用的能力。

## 发布与回滚

基于本设计分支，在独立的草稿实现 PR 中分别准备各个宿主。各适配器拥有独立的包布局与验证结果。先合并本设计，再将各实现 PR 变基至 `main` 并完成验证。实现合并前仍须获得维护者审批。每个实现引用其关联 Issue，仅当该实现合并后满足全部验收标准时才使用关闭引用（`Closes`）。

每个适配器均需附带安装文档与离线检查。在必需的真实宿主运行通过前，将真实安装、工作流与隔离性结果明确标注为未验证；通过后据此更新支持矩阵。保持既有宿主行为与测试不受影响。损坏的集成可独立回退，同时下调其支持声明并保留失败记录，不得删除用户的无关配置。

版本发布独立推进。将新适配器纳入正式发布前，必须重新生成产物包并验证精确候选。
